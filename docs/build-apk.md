# How to build the APK

The icon pack is a small Android app in `iconpack/`. Its icons and XML files are generated by
`scripts/build_iconpack.py`, so always run that script before building.

## Requirements

| Tool | Version | Notes |
|---|---|---|
| JDK | 17 or newer | e.g. Eclipse Temurin 17 |
| Android SDK | platform `android-36` | Android Studio, or the command-line tools |
| Python | 3.11+ | with `requirements.txt` installed (see [how-to-make-icons.md](how-to-make-icons.md)) |
| Gradle | none to install | the project ships the Gradle wrapper (9.8.2) |

**SDK with command-line tools only:** unpack the tools to `<sdk>/cmdline-tools/latest/`, then run

```bash
<sdk>/cmdline-tools/latest/bin/android sdk install platforms/android-36
```

(older tool versions use `sdkmanager "platforms;android-36"`). The build downloads the
build-tools it needs by itself.

The build finds the SDK through `ANDROID_HOME`, or `%LOCALAPPDATA%\Android\Sdk` on Windows.
`build_iconpack.py` writes that location into `iconpack/local.properties`.

## Build

```bash
# 1. regenerate icons and pack resources
python scripts/make_icons.py
python scripts/build_iconpack.py

# 2. build (Windows)
cd iconpack
set JAVA_HOME=C:\Program Files\Eclipse Adoptium\jdk-17...   # PowerShell: $env:JAVA_HOME = '...'
gradlew.bat assembleDebug

# 2. build (macOS / Linux)
cd iconpack
./gradlew assembleDebug
```

The APK is written to `iconpack/app/build/outputs/apk/debug/app-debug.apk`. The first build
downloads Gradle and the Android Gradle Plugin and takes a few minutes; later builds take
about 20 seconds.

## Install

```bash
adb install -r iconpack/app/build/outputs/apk/debug/app-debug.apk
```

Or copy the APK to the phone and open it. Then apply the pack from your launcher (see the
[README](../README.md#apply-in-nova-launcher)). Launchers cache icons, so after an update switch
the icon pack away and back again to see new icons.

## Versioning

Bump `VERSION_CODE` (an integer that must always go up) and `VERSION_NAME` at the top of
`scripts/build_iconpack.py` for every release, then re-run it and rebuild.

## Signing

`assembleDebug` signs with the Android **debug key** of the machine that built it. Android only
installs an update over an existing install when both are signed with the same key. So:

- If you install a build from a different machine (or from GitHub Releases), uninstall the old
  copy first.
- For a store release, create your own release keystore with `keytool`, keep it **out of git**
  (`*.jks` and `*.keystore` are already ignored), add a `signingConfigs` block to
  `iconpack/app/build.gradle.kts` that reads its passwords from environment variables, and run
  `gradlew assembleRelease`.

## What the generator produces

| File | Used by |
|---|---|
| `res/xml/appfilter.xml`, `assets/appfilter.xml` | launchers: component → icon, plus the `iconback` tile for unthemed apps |
| `res/xml/drawable.xml`, `assets/drawable.xml` | Nova's manual icon picker |
| `res/values/iconpack.xml` | ADW icon list and the labels used by the in-app search |
| `res/drawable-nodpi/*.png` | the icons |
| `AndroidManifest.xml` | intent filters that let Nova, Lawnchair, ADW, Apex and others find the pack |

## Exporting for a vivo / iQOO theme (future)

The vivo theme store has no public upload path, so this is preparation only. Check vivo's
current theme-designer documentation first.

- Theme packages usually name icon images by app package; `mapping/components.txt` lists the
  package of every icon.
- Change `SIZE` in `scripts/make_icons.py` to render other sizes. If vivo applies its own icon
  mask, render a tile-less variant (only the glyph group from `svg_for`).
- Wallpapers are already at the native 1080 × 2392.
